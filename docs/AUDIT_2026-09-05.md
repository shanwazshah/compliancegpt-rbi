# ComplianceGPT project audit

Date: 2026-09-05. Scope: current workspace source, API, agent, retrieval, ingestion, deployment, tests, and saved evaluations. This is a software audit, not verification of RBI rules or legal accuracy. No source fixes were applied. Existing changes in app/config.py and docs/PROJECT_SPEC.md were preserved. Secret values in .env were not inspected.

## Assessment

Do not treat the current build as production-ready. The deployment build has a packaging blocker, production configuration does not pass through authentication, and several answer-validation and temporal-correctness paths can return misleading results. The code is modular and lint passes, but existing unit tests miss the reproduced cases below.

P1 means fix before production use; P2 means a material correctness or reliability issue to address next. Findings marked static were established by source inspection, rather than a live deployment or external service test.

## Findings

### 1. P1 — Docker installs packages before copying their directories

Location: Dockerfile:14–19; pyproject.toml package configuration.

Only pyproject.toml exists when `pip install -e .` runs, but setuptools explicitly requires app, ingestion, and evals. The source COPY occurs later. Reproducing the package-build step in an empty temporary directory produced `DistutilsFileError: package directory 'app' does not exist`.

Fix: install dependencies separately for layer caching, then copy source and install the project; alternatively copy package directories before project installation. Verify with an actual clean Docker build. A complete Docker image build was not run in this audit.

### 2. P1 — Production authentication is omitted, and the unauthenticated limiter is bypassable

Locations: docker-compose.prod.yml:32–42; app/api/security.py:35.

The Compose app environment forwards LLM_API_KEY but omits API_KEY. The image excludes .env. Setting API_KEY in the host shell or Compose interpolation file therefore does not configure application authentication unless the service definition is also changed. The published API defaults to accepting anonymous queries.

In that mode, the limiter trusts any supplied X-API-Key as a client identity. Reproduction: with rate_limit_per_min=1, the same fake IP successfully made three calls using three arbitrary headers. This allows anonymous clients to bypass the limit and consume inference resources.

Fix: explicitly pass a required production API_KEY, fail closed for production, and base anonymous limits on a trusted client identity rather than an unvalidated header. Update the Streamlit client to send the configured key (ui/streamlit_app.py:67 currently sends none).

### 3. P1 — Cache hits bypass resolved temporal scope

Locations: app/agent/graph.py:233–241; app/agent/cache.py:25–35.

Cache lookup occurs before classification/date resolution and is keyed by the raw reference_date argument. All requests without an explicit argument use None, including natural-language historical dates and “today.” A cached answer survives midnight and corpus updates until eviction or restart; sufficiently similar questions with different embedded dates can also collide.

Reproduction with a fake embedding provider: an entry with reference_date_used=2026-09-04 stored under None is returned unchanged for an undated request. The cache never checks the current date, corpus revision, or resolved answer date.

Fix: resolve and validate date before lookup; key by the resolved ISO date and corpus/model/prompt versions. Add bounded expiry and invalidation on ingestion. Test midnight and natural-language date changes.

### 4. P1 — Temporal filtering retires whole documents for amendments and ignores commencement

Location: app/retrieval/temporal_filter.py:31–38; migrations/0001_init.sql.

The NOT EXISTS clause excludes a predecessor for every effective edge, including the supported amends and partially_supersedes relation types. A partial amendment therefore removes unaffected provisions from retrieval. The filter also uses issue_date without checking documents.effective_date, allowing a future-commencing document to appear in force after publication but before commencement. Draft status is not excluded either.

Evidence: static SQL/schema inspection. Existing temporal tests cover a complete consolidation pair, not these cases. This is a defect in supported schema behavior; this audit did not establish that the current corpus contains affected rows.

Fix: use commencement dates, exclude drafts, and distinguish whole-document replacement from amendments requiring provision-level handling. Add fixtures for each boundary.

### 5. P1 — Wrong regulatory numbers can receive perfect groundedness

Location: app/agent/nodes/groundedness.py:35–38.

The tokenizer ignores one- and two-character values and removes negation words. Reproduction: source “The minimum ratio is 15 percent.” and answer “The minimum ratio is 99 percent.” score 1.0. The pipeline consequently presents the answer without a low-confidence warning. Word overlap also cannot distinguish a statement from its negation.

Fix: preserve and validate numbers, units, and negation; use claim-level support checks for confidence decisions. Label lexical overlap as an overlap metric rather than evidence of factual correctness. Test numerical and negation contradictions.

### 6. P2 — Context expansion drops retrieved evidence from long sections

Location: app/agent/nodes/expand.py:38–40.

Expansion keeps only the first hit for each parent, while retaining only a 3,000-character window of that parent. Other retrieved children in distant parts of the same chapter are discarded even when outside that window.

Reproduction: two matching children separated by 5,000 characters in one parent produce a context that omits the second child. The existing test uses a tiny parent and does not expose the loss.

Fix: merge overlapping windows but retain disjoint windows within an explicit total token budget. Check that selected child evidence is preserved.

### 7. P2 — Re-indexing does not remove obsolete chunks

Location: ingestion/indexing/embed_and_upsert.py:59–93.

Stable point IDs overwrite surviving chunk indices, but upsert never deletes indices absent from the new version. When a revised document produces fewer chunks, old tail chunks remain searchable under the still-allowed doc_number. A document producing zero children returns before any cleanup.

Evidence: static inspection; no production Qdrant mutation was attempted.

Fix: replace each document's point set atomically where possible, or stage versioned data and switch an active-version filter after successful indexing. Delete obsolete points only after replacement succeeds. Test shrinking and empty documents.

### 8. P2 — Invalid reference dates reach an uncaught exception

Locations: app/api/routes.py:21; app/agent/graph.py:49.

QueryRequest accepts any string as reference_date. Reproduction: `not-a-date` passes request-model validation. For an in-scope request, date.fromisoformat then raises outside the graceful-generation error handler, resulting in an internal error rather than a validation response. Classifier-produced dates are also unchecked.

Fix: validate external dates as a date field and validate classifier output before temporal resolution. Test invalid calendar dates and malformed classifier JSON/date values.

### 9. P2 — Saved citation accuracy fails the configured quality gate

Locations: evals/reports/latest_metrics.json:13; evals/thresholds.json:27.

Running `python -m evals.gate` exits 1: citation_accuracy=54.237% against a 60% floor, a shortfall of 5.8 percentage points. The saved evaluation is dated 2026-08-03 and identifies commit d87bcdfe05206e4f46553a7b7b98fffb7cb3c042; this is evidence about that saved run, not a fresh measurement of the working tree.

Fix: investigate wrong and missing citations using saved answers, improve generation/verification, and run a fresh versioned evaluation before release. CI checks saved metrics without requiring them to match the candidate commit, so passing old metrics would not establish current quality. Do not lower the floor merely to clear this failure.

### 10. P2 — Answer logging bypasses PII redaction

Location: app/api/routes.py:151.

Query text and feedback are redacted, but answer_text is inserted verbatim. If a generated answer echoes a user's PAN/account number, that value is persisted despite redacting the question. The output guard does not remove PII, and a small red-team result with no echoes is not an enforcement mechanism.

Evidence: static data-flow inspection; no actual private user data was used.

Fix: apply redaction to answer text before persistence and avoid logging raw stripped model output. Add a log-boundary test with synthetic PII in both question and answer.

## Additional observations

- API health always returns HTTP 200 even when dependencies are down. The Docker healthcheck checks HTTP success only, so it can mark an unusable service healthy. Separate readiness and liveness checks.
- Feedback requires a query_log_id that the query endpoint neither returns nor obtains from insert_query_log. The public query-to-feedback flow cannot obtain its required identifier.
- The PDF parse cache is keyed only by filename stem, not content hash; replacing a PDF at the same path will reuse old parsed text unless force=True is explicitly used.
- Historical circulars being metadata-only, and the missing SEBI corpus, are already documented limitations rather than newly discovered defects. Empty citations passing temporal metrics must not be interpreted as historical answer quality.

- Isolated reproductions: confirmed limiter bypass, lost expanded evidence, perfect score for a numerical contradiction, unvalidated request date, stale cache date, and missing-package build failure.
- No paid LLM evaluation, live security attack, corpus re-ingestion, or complete Docker build was performed.

Final pytest result: 110 passed, 3 setup errors, 2 warnings in 36.73 seconds. All three errors were PostgreSQL connection timeouts in tests/test_temporal_resolution.py; those integration scenarios remain unverified. This is not a clean full-suite pass.
